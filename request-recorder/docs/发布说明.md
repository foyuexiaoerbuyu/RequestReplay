# RequestRecorder 构建与发布说明

版本：`1.0.0`（所有模块版本保持一致，由父 POM 统一管理）

## 一、模块与产物清单

| 模块 | 产物 | 用途 |
| --- | --- | --- |
| `request-recorder-parent` | pom | 父 POM，统一版本与依赖管理 |
| `request-recorder-core` | jar | 纯 Java 核心（无 Spring / Servlet 依赖） |
| `request-recorder-spring-boot-starter` | jar | 版本无关公共自动装配（不含 Servlet 代码） |
| `request-recorder-spring-boot-2-starter` | jar | Boot 2 适配（`javax.servlet` + `spring.factories`） |
| `request-recorder-spring-boot-3-starter` | jar | Boot 3 适配（`jakarta.servlet` + `AutoConfiguration.imports`） |
| `request-recorder-integration-tests-boot2` | jar | Boot 2 端到端测试（不发布，建议 `deploy` 时跳过） |
| `request-recorder-integration-tests-boot3` | jar | Boot 3 端到端测试（不发布，建议 `deploy` 时跳过） |

业务工程实际只需要引入 `request-recorder-spring-boot-2-starter` 或 `request-recorder-spring-boot-3-starter` 其中一个，core 与公共 starter 会通过传递依赖自动带上。

## 二、环境要求

| 项目 | 要求 |
| --- | --- |
| JDK（core / Boot 2 模块） | 8 及以上（`maven.compiler.release=8`） |
| JDK（Boot 3 模块） | 17 及以上（`maven.compiler.release=17`） |
| Maven | 3.6 及以上 |
| 数据库 | MySQL 8.0（采集库） |

说明：Boot 3 模块需用 JDK 17 编译。若本机默认 `JAVA_HOME` 为 JDK 8，请在全量构建时临时切换到 JDK 17（Boot 2 相关模块仍按 release 8 输出字节码，不影响 Boot 2 工程使用）：

```powershell
$env:JAVA_HOME = 'D:\01App\01dev\zip_jdk\jdk-17.0.20.1+1'
```

## 三、本地安装

```bash
cd request-recorder
mvn clean install
```

该命令会：编译全部模块 → 运行 core 单元测试与 Boot 2 / Boot 3 端到端测试 → 安装到本地仓库（`~/.m2/repository/com/requestrecorder/...`）。

跳过测试的快速安装：

```bash
mvn clean install -DskipTests
```

只装业务必需的三个模块：

```bash
mvn -pl request-recorder-core,request-recorder-spring-boot-starter,request-recorder-spring-boot-2-starter install -DskipTests
```

安装完成后，业务工程直接写依赖版本 `1.0.0` 即可，无需再配置仓库。

## 四、发布到私服（Nexus / Artifactory）

### 1. 在父 POM 中声明分发仓库

父 `pom.xml` 已预留 `distributionManagement` 位置，按实际私服填写：

```xml
<distributionManagement>
    <repository>
        <id>releases</id>
        <name>Internal Releases</name>
        <url>http://nexus.example.com/repository/maven-releases/</url>
    </repository>
    <snapshotRepository>
        <id>snapshots</id>
        <name>Internal Snapshots</name>
        <url>http://nexus.example.com/repository/maven-snapshots/</url>
    </snapshotRepository>
</distributionManagement>
```

### 2. 配置 `~/.m2/settings.xml` 认证

```xml
<settings>
  <servers>
    <server>
      <id>releases</id>
      <username>deployer</username>
      <password>******</password>
    </server>
    <server>
      <id>snapshots</id>
      <username>deployer</username>
      <password>******</password>
    </server>
  </servers>
</settings>
```

### 3. 执行发布

```bash
# 发布正式版（版本号不带 -SNAPSHOT 时推到 releases 仓库）
mvn clean deploy -DskipTests

# 发布测试版（版本号需为 1.0.0-SNAPSHOT）
mvn clean deploy -DskipTests -Drevision=1.0.0-SNAPSHOT
```

建议发布时跳过两个集成测试模块（它们只用于自测）：

```bash
mvn clean deploy -DskipTests -pl request-recorder-core,request-recorder-spring-boot-starter,request-recorder-spring-boot-2-starter,request-recorder-spring-boot-3-starter
```

### 4. 业务工程拉取

业务工程只需保证 `<repositories>` 能访问该私服（或在 `settings.xml` 的 mirror 中聚合），然后：

```xml
<dependency>
    <groupId>com.requestrecorder</groupId>
    <artifactId>request-recorder-spring-boot-3-starter</artifactId>
    <version>1.0.0</version>
</dependency>
```

## 五、产物结构核对

发布前建议核对两个 Starter 的 jar 内容，确保自动装配描述符就位：

```bash
# Boot 2：应存在 META-INF/spring.factories
unzip -l request-recorder-spring-boot-2-starter/target/request-recorder-spring-boot-2-starter-1.0.0.jar | grep spring.factories

# Boot 3：应存在 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
unzip -l request-recorder-spring-boot-3-starter/target/request-recorder-spring-boot-3-starter-1.0.0.jar | grep AutoConfiguration.imports
```

依赖方向约束（构建时会自然满足，勿人为破坏）：

- `request-recorder-core` 不得引入任何 Servlet API 与 Spring Boot 依赖。
- Boot 2 Starter 不得出现 `jakarta.servlet`。
- Boot 3 Starter 不得出现 `javax.servlet`。

可用以下命令自查：

```bash
mvn -pl request-recorder-spring-boot-2-starter dependency:tree | grep -i jakarta   # 应无输出
mvn -pl request-recorder-spring-boot-3-starter dependency:tree | grep -i javax     # 应无 servlet 相关输出
```

## 六、版本管理约定

1. 三个发布模块（core、Boot 2 Starter、Boot 3 Starter）版本必须一致，统一改父 POM 的 `<version>`。
2. 公共 starter 版本随父 POM 走，业务工程不直接引用它。
3. 升级 Boot 小版本时，改父 POM 的 `spring-boot-2.version` / `spring-boot-3.version` 后重跑集成测试。
4. 表结构若新增字段，必须同步：`sql/request_recorder.sql`、`RecordData`、`RecorderRepository`、Python GUI 查询与详情展示、Python 回放逻辑。

## 七、发布前检查单

- [ ] `mvn clean install` 全绿（core 单测 + Boot 2 / Boot 3 端到端测试）
- [ ] `sql/request_recorder.sql` 可在 MySQL 8.0 上重复执行
- [ ] 两个 Starter 的自动装配描述符已打包
- [ ] 依赖方向检查无越界（core 无 Servlet、Boot 2 无 jakarta、Boot 3 无 javax）
- [ ] 文档（使用 / 配置 / 发布 / 兼容性）与技术实现一致
- [ ] 示例配置中不含真实密码
